# P2 Verification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans.

**Goal:** A submitted opinion becomes a verified review: claims → per-claim retrieval → Claude verification → deterministic validation, score, status → report (+ suggested opinion) → similar opinions, with SSE progress.

**Architecture:** `POST /reviews` stores the opinion (text or file in S3) and enqueues `run_review`. The worker runs the pipeline in `app/verification/` and publishes stage events on Redis (`review:{id}`), which `GET /reviews/{id}/events` streams as SSE. Claude is called only through `app/llm/claude_client.py` (forced tool use, temperature 0, cached system prompt, retries, `llm_calls` row per call). Score/status/blocking are pure Python.

**Tech Stack:** anthropic SDK, rapidfuzz, PyMuPDF/python-docx, arq, Redis pub/sub, FastAPI StreamingResponse.

**Spec:** `docs/BRIEF.md` §1, §2 (FR-1…FR-8, FR-11, FR-16), §6.7, §7, §8; `CONTEXT.md`.

## Global Constraints

- LLM: Anthropic Claude only, model `claude-sonnet-4-5`, temperature 0, structured output via forced tool use, prompt caching on static system prompts, retry with backoff then a clean Arabic error.
- The LLM never emits score/status; Python computes them. Evidence quotes ≤ 40 words, verbatim-validated.
- Fixed no-information message: `لا تتوفر معلومات في المصادر المتاحة للتحقق من هذا الرأي.`
- Resolved-conflict badge: `تعارض محسوم لصالح المصدر الأعلى`.
- Weights core=2 / supporting=1; factual_premise excluded. Values 1 / 0.5 / 0 / 0. ACCEPT_THRESHOLD=90. MAX_CLAIMS=40. PER_CLAIM_K=6. ≤ 6 claims per verification call. ≤ 6,000 evidence tokens per claim, ≤ 40,000 per call.
- Retrieval reuses `app.retrieval.search.search(mode="full")` — no second retrieval path.

## Review Focus

1. Hallucinated passage IDs / non-verbatim quotes never reach the report.
2. A repealed source can never be `supports`.
3. Blocking vs resolved contradictions follow the authority / lex-posterior rule.
4. A user can only read their own reviews (reviewers/admins: all); ACL scopes retrieval.
5. Claude/TEI failures mark the review `failed` with an Arabic message, never a fake result.

### Task 1: Claude client — `call_structured` + llm_calls logging
**Files:** `backend/app/llm/claude_client.py`, `backend/app/core/config.py` (claude_model, pricing), tests.
**Produces:** `ClaudeClient.call_structured(system: str, user: str, tool_name: str, schema: dict, *, review_id=None, prompt_version: str, max_tokens=4096) -> dict`; `LLMUsage` rows.
- [ ] Test (fake SDK): forces `tool_choice={"type":"tool","name":tool_name}`, `temperature=0`, system block has `cache_control`; returns tool input; retries transient errors then raises `ClaudeError`; writes an `llm_calls` row with tokens + cost.

### Task 2: Opinion parsing
**Files:** `backend/app/verification/parse.py`, tests. **Produces:** `extract_text(filename: str, data: bytes) -> str` (pdf/docx/txt); `ParseError` (Arabic message) for scanned/empty/unsupported.

### Task 3: Claim extraction
**Files:** `backend/app/verification/extract.py`, `backend/app/verification/prompts.py`, tests.
**Produces:** `ClaimIn` dataclass `{id, text_ar, type, materiality, cited_refs}`; `async extract_claims(llm, opinion, question) -> list[ClaimIn]` (cap MAX_CLAIMS, dedupe).

### Task 4: Evidence assembly
**Files:** `backend/app/verification/passages.py`, tests (integration).
**Produces:** `Passage {pid, chunk_id, unit_id, text, context_header, title_ar, number, year, article_label, doc_type, authority, status, effective_date, valid_from, valid_to, parent_text}`; `async gather_passages(session, claims, as_of, collections, allowed) -> dict[claim_id, list[Passage]]` with global P# ids deduped by unit, pinned refs from `cited_refs`, parent expansion for `clause_split`, per-claim token budget.

### Task 5: Verification calls
**Files:** `backend/app/verification/verify.py`, tests.
**Produces:** `async verify_claims(llm, claims, passages, review_id) -> dict[claim_id, RawVerdict]`, batches ≤ 6 claims and ≤ 40k tokens, bounded concurrency.

### Task 6: Validation + scoring + status (pure Python)
**Files:** `backend/app/verification/validate.py`, `backend/app/verification/scoring.py`, tests.
**Produces:** `validate(raw, passages, as_of) -> ValidatedClaim` (drops hallucinated ids / unverified quotes, relabels repealed supports, downgrades verdicts); `score_review(claims) -> (score, status, blocking_map)`.

### Task 7: Report + suggested opinion + similar opinions
**Files:** `backend/app/verification/report.py`, tests.
**Produces:** `async write_report(llm, validated, status) -> {summary_ar, suggested_opinion_ar}` with `[P#]` markers validated; `async similar_opinions(session, text, allowed) -> list[dict]` top 5 by document.

### Task 8: Pipeline + worker task + progress events
**Files:** `backend/app/verification/pipeline.py`, `backend/workers/tasks.py`, `backend/app/core/events.py`, migration 0003 (`reviews.error_ar`, `reviews.title`), tests (integration with fake LLM/TEI).
**Produces:** `async run_review(ctx, review_id)`; persists claims, claim_evidence, review_versions (`ai_report`, `ai_suggested_opinion`), approvals (`system_accept` when accepted), config_snapshot.

### Task 9: Reviews + sources API
**Files:** `backend/app/api/reviews.py`, `backend/app/api/sources.py`, tests.
**Produces:** `POST /api/v1/reviews` (multipart) → 202 `{review_id}`, daily limit → 429; `GET /api/v1/reviews`, `GET /api/v1/reviews/{id}`, `GET /api/v1/reviews/{id}/events` (SSE); `GET /api/v1/sources/chunks/{id}`.
